# ADR-0001: доставка истории точек снимком и live-пакетами

- Статус: принято
- Дата: 2026-08-28

## Контекст

Каждый из десяти источников создаёт до 1 800 точек. История должна переживать пересоздание
`Activity` и быть доступной нескольким экранам, но повторная выдача тысяч отдельных событий через
`SharedFlow(replay)` перегружает главный поток при создании новой SciChart-поверхности. Размер replay
также не должен быть неявным ограничением для будущего серверного или локального источника.

## Решение

Репозиторий разделяет хранение и доставку:

1. В памяти каждого источника хранится полная история в порядке поступления.
2. Подписчик атомарно получает один неизменяемый снимок истории и регистрируется для live-данных.
3. Новые точки передаются непустыми пакетами через ограниченный канал с backpressure.
4. `ViewModel` преобразует целый пакет на `DefaultDispatcher`.
5. UI объединяет полученные пакеты до одной операции `SciChart append` на кадр.

Снимок и регистрация выполняются под одной короткой синхронизацией. Поэтому между ними нет окна,
в котором точка могла бы потеряться или прийти раньше снимка. Приостановка отправки происходит вне
критической секции.

## Последствия

Плюсы:

- восстановление экрана создаёт по одному событию на источник вместо тысяч событий;
- история не ограничена транспортным параметром replay;
- очередь ограничена, поэтому медленный UI не вызывает неограниченный рост памяти;
- контракт одинаков для генератора, базы данных и backend-потока;
- преобразование моделей не блокирует главный поток.

Компромиссы:

- in-memory история занимает память пропорционально числу точек;
- медленный потребитель создаёт backpressure для соответствующего источника;
- при переходе к неограниченному серверному потоку потребуется явная retention-политика
  (временное окно, дисковое хранилище или downsampling), заданная требованиями продукта.

Для текущего задания верхняя граница детерминирована: 18 000 точек суммарно. Производительность UI
контролируется отдельным Macrobenchmark на release-подобной сборке.
